HOW TO READ THIS BOARD

数字有口径，结论有出处。

这是协作快照，不是自动验收系统。

01 / 工作量

任务权重 × 阶段进度

每人的任务权重合计 100%，取整到 5%。三人预计工作量分配为 45% / 45% / 10%。粗估可以修订，不能冒充实际工时或验收率。

02 / 代码量

只数主线产品源码

统计指定 Rust 与 MATLAB 适配源码的非空行，含注释。排除老师原始程序、模型、测试证据、文档和生成数据；预估目标可调整，代码多不等于功能正确。

03 / 提交时间

GitHub PR 为事实来源

列表及成员“最近提交”均使用 PR 的 created_at，不使用本地文件时间。弹窗另列 updated_at 与合并时间，防止把更新当成新交付。

04 / 审核意见

通过有范围，也有版本

意见由指挥审核记录登记。HEAD 更新则自动转为待复审；CI 绿色、开发者自测和已合并都不自动代表完整验收。新界面仍须本人明确认可。

公开摘要，源码保持私有。
